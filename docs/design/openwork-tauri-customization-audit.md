# OpenWork Tauri customization audit

## Scope

This audit compares the OpenWork merge parent `547c885` with the qwen-code
v0.21.10 merge parent `4356c1c`, then maps user-visible OpenWork behavior onto
the current Tauri + `packages/web-shell` architecture.

The old Electron implementation is evidence of intended behavior, not the
migration target. A feature is not considered preserved merely because its
Electron files still exist under `apps/electron` or `packages/desktop`.

Status values:

- **Preserved** — implemented on the Tauri/Web Shell path.
- **Upstream equivalent** — qwen Web Shell already provides equivalent behavior.
- **Partial** — some behavior exists, but parity is incomplete.
- **Missing** — not present on the Tauri/Web Shell path.
- **Tauri redesign** — Electron-specific behavior needs a Tauri implementation.
- **Historical only** — should not be migrated because the target architecture supersedes it.

## PR1 preservation gate

PR1 is complete only when all of the following are true:

1. Tauri loads the qwen Web Shell, not the Electron renderer.
2. The original OpenWork renderer symbol and application identity are visible.
3. A real workspace can create or load a session, send a prompt, and receive a response.
4. Restart and quit terminate the bundled daemon without an orphan process.
5. The packaged runtime contains the qwen CLI, Web Shell and matching Node runtime.
6. Rust tests, Web Shell checks, runtime smoke and packaged smoke pass.

The remaining product enhancements and all Electron-native capabilities stay
tracked above for PR2; they are not silently discarded and are not PR1 blockers.
